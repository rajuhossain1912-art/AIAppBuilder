# AIAppBuilder Privacy Policy

## 1. Purpose

This policy defines how AIAppBuilder protects user, client, project, and application data.

Privacy is a core system requirement.

## 2. Core Principles

AIAppBuilder must follow:

- Data minimization
- Purpose limitation
- Project isolation
- Least-privilege access
- Secure processing
- Transparent handling
- User control
- No unnecessary data sharing

## 3. Private-by-Default

AIAppBuilder is a private personal development agent.

Project information should remain private unless the user explicitly authorizes sharing or publication.

## 4. Data Categories

The system may process:

- User requests
- Project requirements
- Source code
- Build information
- Test results
- Research records
- Project memory
- Audit records
- Generated artifacts
- Configuration metadata

Only necessary information should be retained.

## 5. Sensitive Data

Sensitive information must receive stronger protection.

The system must not unnecessarily collect or retain:

- Passwords
- API keys
- Access tokens
- Private keys
- Payment credentials
- Authentication cookies
- Unrelated personal information

Secrets must not become ordinary searchable memory.

## 6. Client Data

Client information supplied for application development must remain associated with the correct project.

Client information must not be disclosed to another client or unrelated project.

## 7. Project Isolation

Each project must maintain separate:

- Requirements
- Source code
- Memory
- Audit history
- Build records
- Test results
- Research records
- Artifacts
- Client information

Cross-project reuse must not expose private information.

## 8. External Services

Before sending information to an external service, the system should determine:

- Why the data is required
- What data will be transmitted
- Whether transmission is authorized
- Whether a less-data alternative exists
- Security implications
- Privacy implications
- Cost and quota implications

Only necessary data should be transmitted.

## 9. Research Privacy

When performing web or external research, private project information should not be included unnecessarily.

The Agent should prefer generalized queries when the private details are not required.

## 10. AI Provider Privacy

If an external AI provider is used, the system should minimize the information sent to that provider.

Private source code, client information, credentials, and unrelated project data must not be transmitted unless necessary and authorized.

## 11. Storage

Stored information should be protected against unauthorized access.

Where technically supported, sensitive data should use appropriate encryption at rest and in transit.

## 12. Memory Privacy

Long-term memory should store useful information without unnecessarily storing private details.

The system should distinguish:

- Global reusable knowledge
- Project-specific knowledge
- Client-specific information
- User-private information
- Temporary session information

Project-private information must not automatically become global knowledge.

## 13. Audit Privacy

Audit records should contain enough information to reconstruct important actions while avoiding unnecessary sensitive data.

Secrets must never be written into ordinary audit logs.

## 14. Artifact Privacy

Generated APKs, source archives, reports, and other project artifacts should inherit the privacy classification of their project unless explicitly changed.

Private artifacts must not be publicly exposed without authorization.

## 15. Public Release

The Agent must not publish private project information, source code, APKs, reports, or client data publicly without appropriate authorization.

## 16. User Control

The user should be able to request information about:

- What project data is stored
- What memory exists
- What external services were used
- What information was transmitted
- What artifacts were generated

The Agent should answer from available records rather than guessing.

## 17. Correction

If stored project information is incorrect, the system should preserve historical integrity while recording an appropriate correction.

Historical records must not be silently rewritten.

## 18. Deletion

Deletion of important project or historical information should follow the applicable approval and retention rules.

The Agent must not silently delete important history.

## 19. Backup Privacy

Backups must receive protection appropriate to the original data.

Creating a backup must not automatically make private information public.

## 20. Migration Privacy

When moving from GitHub or another provider to a new storage system, the migration must preserve applicable privacy controls.

Private information must not be exposed during migration.

## 21. Provider Independence

Changing an external provider must not weaken privacy requirements.

A new provider must be evaluated before private project data is transferred.

## 22. Access Control

Access to project information must follow least privilege.

Only authorized components should access private project data.

## 23. No Cross-User Leakage

Information belonging to one user must never be exposed to another unauthorized user.

## 24. Data Minimization

The system should collect and retain only information reasonably necessary for:

- Development
- Testing
- Verification
- Delivery
- Project history
- Security
- Recovery

## 25. Retention

Important project history should remain available for long-term recall according to the memory policy.

Data should not be deleted merely because it is old unless an applicable retention rule requires deletion.

## 26. Privacy Failure

If the system detects a possible privacy violation:

1. Stop the affected operation when possible.
2. Prevent further unnecessary disclosure.
3. Record the security/privacy event without exposing the sensitive data.
4. Determine the scope.
5. Take appropriate recovery action.
6. Inform the user when required.

## 27. No False Privacy Claims

The Agent must not claim that data is:

- Private
- Encrypted
- Deleted
- Never transmitted
- Permanently retained

unless that property is actually supported and verified.

## 28. Privacy and Generated Apps

Applications created by AIAppBuilder should collect only data necessary for their declared functionality.

Generated applications should:

- Request appropriate permissions
- Avoid unnecessary data collection
- Protect sensitive information
- Use secure network communication
- Avoid unnecessary third-party data sharing

## 29. Privacy and Accessibility

Accessibility functionality must not require unnecessary collection of personal information.

Accessibility-related data should be processed only when necessary for the requested functionality.

## 30. Final Rule

AIAppBuilder must treat user and client information as private by default.

Its privacy process is:

MINIMIZE
→ CLASSIFY
→ ISOLATE
→ AUTHORIZE
→ PROTECT
→ AUDIT
→ RETAIN OR DELETE ACCORDING TO POLICY

Privacy must not be sacrificed for convenience or speed.
